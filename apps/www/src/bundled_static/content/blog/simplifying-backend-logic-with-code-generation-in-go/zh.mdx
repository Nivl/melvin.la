后端开发免不了大量重复的样板代码，尤其围绕在数据库查询和 API 服务器上。用手写这些代码既慢又容易出错。代码生成工具（codegen）能把声明式的规格转成型别安全的 Go 代码，你也不用花心力维护。

这篇文章介绍两个工具。

- [sqlc](https://sqlc.dev/) 从 SQL 查询生成 Go 代码。
- [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) 从 OpenAPI 规格生成 Go 服务器代码。

## 为什么要用代码生成

- 样板代码变少。麻烦的部分由生成器一次写完。
- 类型安全度更高。生成的代码强类型，错误在编译时就会出现，而不是运行时。
- 维护更简单。改 SQL 或 API 规格后重新生成就好。
- 开发更快。时间能花在业务逻辑上。

## 用 sqlc 生成 SQL 代码

### sqlc 是什么

sqlc 读取 `.sql` 文件，生成带类型参数和结果的 Go 函数来执行那些查询。

### sqlc 怎么用

1. 写好书据结构（数据表结构）和查询。
2. 在 `sqlc.yaml` 里设置输入与输出。
3. 执行 `sqlc generate`。

### 示例

假设有一个 `users` 数据表。

```sql
-- schema.sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE NOT NULL
);
```

用 email 找出用户的查询如下。

```sql
-- queries.sql
-- name: GetUserByEmail :one
SELECT id, name, email FROM users WHERE email = $1;
```

`sqlc.yaml` 的配置。

```yaml
version: "1"
packages:
  - name: "db"
    path: "./db"
    queries: "./queries.sql"
    schema: "./schema.sql"
    engine: "postgresql"
```

执行：

```bash
sqlc generate
```

会生成像这样的方法。

```go
func (q *Queries) GetUserByEmail(ctx context.Context, email string) (User, error)
```

在后端这样使用。

```go
user, err := dbQueries.GetUserByEmail(ctx, "alice@example.com")
if err != nil {
    // handle error
}
fmt.Println("User:", user.Name)
```

手动处理 SQL 字符串和扫描数据行的工作不见了。代码变得更干净、更安全。

## 用 oapi-codegen 生成服务器代码

### oapi-codegen 是什么

oapi-codegen 从 OpenAPI 规格生成 Go 的服务器和客户端代码。它会创建接口和请求、响应的类型。剩下的就是实现业务逻辑。

### oapi-codegen 怎么用

1. 用 OpenAPI 的 YAML 或 JSON 文件定义 API。
2. 执行 `oapi-codegen`。
3. 实现生成的接口方法。

### 示例

准备一份小的 OpenAPI 规格 `api.yaml`。

```yaml
openapi: 3.0.0
info:
  title: User API
  version: 1.0.0
paths:
  /users/{email}:
    get:
      summary: Get user by email
      parameters:
        - name: email
          in: path
          required: true
          schema:
            type: string
      responses:
        "200":
          description: User found
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/User"
        "404":
          description: User not found
components:
  schemas:
    User:
      type: object
      properties:
        id:
          type: integer
        name:
          type: string
        email:
          type: string
```

生成服务器代码。

```bash
oapi-codegen -generate types,server -package api -o api.gen.go api.yaml
```

这会生成请求、响应的类型（`User` struct），以及带有方法的 `ServerInterface`。

```go
GetUsersEmail(ctx context.Context, email string) (api.User, error)
```

实现接口。

```go
type ServerImpl struct {
    db *db.Queries
}

func (s *ServerImpl) GetUsersEmail(ctx context.Context, email string) (api.User, error) {
    user, err := s.db.GetUserByEmail(ctx, email)
    if err != nil {
        return api.User{}, err
    }
    return api.User{
        Id:    int64(user.ID),
        Name:  user.Name,
        Email: user.Email,
    }, nil
}
```

接上服务器。

```go
router := api.NewRouter(&ServerImpl{db: dbQueries})
http.ListenAndServe(":8080", router)
```

## 同时使用 sqlc 和 oapi-codegen 的好处

- 类型安全从数据库一路延伸到 API 层。
- SQL 和 API 规格保持声明式，跟逻辑分开。
- 开发更快。可以把时间花在业务逻辑上。
- 重构更容易。改 SQL 或规格后重新生成，再修真正有变动的部分就好。

## 结论

同时使用 sqlc 和 oapi-codegen，就能在 Go 后端自动化数据库访问和 API 服务器代码。要写的样板变少了，运行时的错误也变少了。该专注的地方是应用的核心逻辑。
